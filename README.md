# 게임업계 채용 동향

매월 1일 오전 9시(한국시간)에 게임잡 공고를 수집하고, 이전 달 기준 자료와 기업·직무별 변화를 비교합니다.

## 적용

1. 기존 GitHub 저장소에 이 폴더의 수정 내용을 반영합니다. `.github/workflows/scrape.yml`도 포함합니다.
2. 기존 `data/snapshots/2026-08-01.csv`는 삭제합니다. 임시 파일은 `data/examples/2026-08-01.csv`로 보관했습니다. 예전 리포트는 `data/examples/legacy-reports`로 옮겼습니다. ZIP을 덮어쓰기만 하면 이전 경로의 파일이 남을 수 있으니 확인해주세요.
3. 기본 브랜치의 Actions에서 ‘게임잡 채용공고 수집’이 활성화되어 있는지 확인합니다. 저장소 쓰기 권한과 기존 Pages 게시 설정이 필요합니다.
4. 이번 변경은 수정 파일입니다. GitHub 저장소 적용이나 운영 사이트 배포는 아직 수행하지 않았습니다.

## 수집과 비교 기준

- 예약식 `0 0 1 * *`는 UTC 기준으로, 한국시간 매월 1일 09:00입니다.
- GitHub Actions 대기열 때문에 정각 시작을 보장하지 않습니다. 각 CSV 옆 `.meta.json`에 실제 시작·완료 시각을 한국시간으로 기록합니다. 수집은 여러 페이지를 순회하므로 한 순간의 완전한 상태는 아닙니다.
- 해당 월의 첫 성공 자료를 유지합니다. 같은 달 수동 재실행은 기존 자료를 덮어쓰지 않고 종료합니다.
- 요청 실패 또는 사이트 표시 전체 건수에 못 미치는 수집은 저장하지 않고 작업을 실패 처리합니다. 사이트 집계 기준이 바뀌면 수집기를 점검해야 합니다.
- 임시 8월 데이터는 기본 집계에서 제외합니다. 9월 2일 자료는 기존 기준 자료로 남기며 ‘월초 외 수집 자료’로 표시합니다. 다음 정기 예약은 2026년 10월 1일 09:00 KST입니다.
- 자료가 없는 달은 만들지 않습니다. 화면에 실제 비교 날짜가 표시됩니다.
- 신규: 이전 자료에 없고 현재 자료에 있는 공고번호. 소멸: 이전 자료에 있고 현재 자료에 없는 공고번호. 순증감: 전체 공고 수의 차이.
- 월중 생성 후 월중 마감된 공고는 관측하지 못합니다. 소멸은 채용 완료나 감원을 뜻하지 않습니다. 공고 수는 채용 인원이 아닙니다.
- 직무는 복수 집계됩니다. 동일 공고의 회사명/직무가 바뀌면 해당 그룹 순증감과 신규−소멸이 다를 수 있습니다.

## 화면

- 월 선택, 전체·신규·소멸·순증감 카드
- 기업·직무별 증가/감소/신규/소멸 순위
- 신규·소멸 공고 목록, 검색, 더 보기
- 기존 기업 상세, 직무 상세, 고용형태, 월간 AI 리포트, 콩스튜디오 채용, 이력서 분석 기능 유지
- 같은 경로의 `data/snapshots/index.json`을 읽으므로 GitHub API 없이 일반 정적 호스팅에서도 데이터를 불러옵니다. 로컬 파일로 열면 CSV 불러오기를 사용합니다. `index.html`, `monthly.js`, `monthly.css`를 함께 배치하세요.

## 뉴스 리포트

공고 수집·수치 리포트는 자동 실행됩니다. 뉴스 기반 AI 해석은 기존 방식대로 월간 리포트의 생성 버튼과 사용자의 API 키로 실행합니다. 발행일, 출처, 원문 URL을 요구하고 사실과 해석을 구분하도록 보완했습니다. 이 기능의 외부 API 호출은 이번 작업에서 실행·검증하지 않았습니다. 기존 모델 식별자와 계정에서 지원하는 모델도 확인이 필요합니다. API 키와 분석 기록은 기존과 같이 해당 브라우저에 저장됩니다.

## 결과 파일

- `data/snapshots/YYYY-MM-DD.csv`: 월 기준 공고
- `data/snapshots/YYYY-MM-DD.meta.json`: 수집 시간·검증 상태
- `data/reports/YYYY-MM-DD_new_jobs.csv`, `*_removed_jobs.csv`: 신규·소멸 공고
- `data/reports/YYYY-MM-DD_company_changes.csv`, `*_category_changes.csv`: 기업·직무별 이전/현재/신규/소멸/순증감
- 기존 Markdown 및 건수 통계 CSV

## 검증

JavaScript/Python 문법, 공고번호 차집합, 기업별 순증감, 임시 데이터 제외, 월별 첫 자료 선택, 기존 스냅샷 보호, 수집 요청 실패 시 저장 방지를 확인했습니다. 실제 웹 수집, 브라우저 화면 및 외부 AI API는 검증하지 않았습니다.

예약 관련 공식 설명: https://docs.github.com/actions/using-workflows/events-that-trigger-workflows#schedule


## 콩스튜디오 채용 대시보드

### 프로젝트 / 공고

- 프로젝트별 비율은 ‘현재 오픈 상태인 공고 수 / 전체 오픈 공고 수’입니다. 모집 인원이나 채용 완료 비율이 아닙니다.
- 시장 분석에서 선택한 과거 월과 별개로 가장 최신 수집 자료를 사용합니다. 공고가 최신 목록에서 사라져도 기존 후보자를 잃지 않도록 이전 공고를 보존하고 ‘상태 확인 필요’로 표시합니다.
- 공고를 선택하면 프로젝트, 오픈·보류·마감 상태, 실제 오픈일·마감일, 메모를 수정할 수 있습니다. 상태를 직접 설정한 공고는 다음 수집에서도 수동 설정을 유지합니다.
- 공고 제목의 대괄호를 프로젝트 초깃값으로 추정하므로 직접 확인·수정해주세요. 기존 프로젝트·메모는 기본값으로 읽어옵니다.
- 경쟁 공고는 최신 자료에서 동일 직무가 겹치는 타사 공고 최대 10건입니다.

### 후보자

1. 공고 선택 → 후보자명(또는 별칭), 실제 지원일, 메모를 입력합니다.
2. 등록 시 ‘지원’ 단계에 표시됩니다. 기존 진행 후보자는 등록 후 실제 단계와 해당 단계의 시작일을 입력하세요.
3. ‘단계 변경 · 기록’에서 단계와 변경일을 저장합니다. ‘지원 / 서류 검토 / 1차 면접 / 2차 면접 / 처우 협의 / 입사 확정 / 불합격 / 지원 철회’를 지원합니다.
4. 각 후보자에 지원 후 경과일, 현재 단계 체류일, 단계 이력을 표시합니다. 불합격·철회·확정 후보자는 종료일에서 경과 계산을 멈춥니다.
5. 잘못 변경한 마지막 단계는 취소할 수 있습니다. 후보자 삭제는 확인 후 해당 이력까지 제거합니다.
6. 과거 단계 날짜를 모르면 건너뛸 수 있으나, 건너뛴 단계의 소요일은 추정하지 않습니다.

### 리드타임

- 지원→입사 확정: 지원일부터 입사 확정 단계 변경일까지.
- 공고 오픈→입사 확정: 직접 입력한 공고 오픈일부터 각 후보자의 입사 확정일까지.
- 같은 날은 0일이며, 주말·공휴일을 포함한 달력일입니다.
- 상단 평균은 모든 공고의 입사 확정 후보자 기준입니다. 공고 상세에서는 해당 공고의 두 평균을 보여줍니다. 날짜를 입력하지 않은 값은 평균에서 제외합니다.
- 입사 확정은 이 대시보드에서 채용 수락이 확정된 날로 사용합니다. 실제 입사일 및 입사 예정일 추적과는 별개입니다.

### 저장과 공유 범위

후보자와 수정된 공고 정보는 브라우저 localStorage에 저장됩니다. 현재 버전은 개인 관리용이며 그리팅에서 후보자를 자동으로 가져오거나 여러 담당자 사이에서 동기화하지 않습니다. 다른 PC·브라우저로 옮기려면 ‘기록 백업’으로 JSON을 내려받고 ‘백업 복원’을 사용하세요. 복원은 현재 채용 대시보드 기록을 교체합니다. 후보자 이름·메모가 포함되므로 백업 파일도 업무 자료로 관리하세요. 기존 화면의 메모는 새 대시보드에서 공고 정보를 저장한 이후 새 백업에 포함됩니다.

### 추가 검증

한국 날짜, 달력일 계산, 진행/종료 후보자 체류일, 공고 오픈일 누락 시 제외, 저장·복원 형식, 잘못된 이력·중복 ID 차단, 이전 공고 보존과 수동 상태 유지 로직을 확인했습니다. 실제 브라우저 화면과 그리팅 연동은 검증하지 않았습니다.
